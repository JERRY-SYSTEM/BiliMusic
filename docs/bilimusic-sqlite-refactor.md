# BiliMusic SQLite 改造说明

## 1. 名称与无用代码清理

应用显示名、Dart 应用类、播放器类型、媒体信息、权限通信渠道、备份文件名和
CI 发布文件名统一改为 BiliMusic / bilimusic。Android namespace、applicationId
和 MainActivity 包声明为 `com.bilimusic.player`；iOS 的 Debug、Profile、Release
配置使用相同 Bundle ID，测试目标为 `com.bilimusic.player.RunnerTests`。

保留真实 GitHub 仓库链接、远端仓库名称、签名密钥路径与 CI 密钥名称。
没有提高最低系统版本，没有创建提交或发布版本。

清理依据是当前引用关系及以下提交的功能边界：

- `b9610b2`：保留原生队列上限、随机历史上限、请求超时和连接释放、封面解码限制、下载写入背压。
- `401b0e1`：保留 JSON 备份结构和选择性导入行为；仅更换导入的最终提交方式。
- `342a872`：保留播放全部后的队列持久化、选中位置和延迟恢复行为。
- `0b46e57`、`25aa2b7`：保留在线歌单同步及导入失败后的备用恢复路径。
- `f569a4b`、`e98ec88`：保留按歌曲归类的缓存管理及多音质下载。

实际删除：旧 JSON 加载器、版本信封兼容、isolate JSON 文件解析函数、原子文件
写入函数、音频旁车元数据扫描、无调用的下载注册包装、会话 `encode/decode`
字符串接口，以及 17 个未引用的 `AppColors` 常量（包括未使用的渐变及其两个颜色）。
补充了会话控制器释放 HTTP 客户端和轮询计时器的逻辑。

## 3. SQLite、下载与缓存

`AppDatabase` 管理共享连接、SQLite schema version 1、外键、事务以及测试工厂/路径
注入。数据保存在 `bilimusic.db`。复杂模型字段仍按单条记录编码在 payload 列中，
关系、排序和下载索引为独立 SQL 列；不再把整个应用状态保存为 JSON 文件。

| 表 | 用途 |
| --- | --- |
| tracks | 按完整 `track.id` 保存歌曲元数据，保留分 P 身份 |
| playlists / playlist_tracks | 歌单属性、歌单顺序和有序去重成员 |
| downloaded_tracks / downloads | 本地列表顺序，以及歌曲 ID + 音质对应的文件路径和字节数 |
| recently_played / search_history | 最近播放 50 条、搜索历史 12 条，保留去重顺序 |
| lyrics | 按歌曲保存歌词内容及缓存顺序，常规缓存上限 200 条 |
| settings / session | 外观、默认音质及登录会话 |
| playback_state / playback_queue | 播放模式、进度、当前索引及播放/自然顺序队列，允许队列重复项 |

音乐库读取返回独立对象。事务成功后才发送更新事件；设置和会话提交成功后才更新
内存及通知。歌曲信息更新通过同一个歌曲记录反映到歌单、历史、本地列表和持久化
播放队列。已无任何关系引用的歌曲记录会清理，避免有限历史导致元数据无限增长。

下载继续使用 `.part` 支持断点续传。文件完成落盘后，在事务中登记音质记录及
本地列表；数据库写入失败不会产生完成事件。取消 JSON 旁车和 `.ready` 标记。
读取本地库时校验文件存在性和大小，删除失效索引；未登记文件进入缓存“其它”分类。
分 P 文件删除按完整 ID 匹配，不会因前缀相同误删 P10 等其他分 P。

缓存页通过 SQL 查询歌词内容字节数，通过下载索引归属音频。删除“其它”时同步清除
相应歌词记录；数据库文件本身不被当作缓存删除。删除失败会显示错误提示。

旧 JSON 和旧目录既不加载也不自动迁移，不主动删除。音频、封面和临时文件仍存于
文件系统，新音频/封面目录使用 bilimusic 前缀。

## 4. 导入导出

继续接受旧版导出的 `schemaVersion: 1` JSON，保留预览、选择登录信息/收藏/歌单、
去重、自定义歌名歌手、手动歌词以及在线歌单同步失败计数。

导入先完成最多 4 路并发的数据补全和网络同步，再一次性提交歌单、歌词、歌曲修改
以及选中的会话。事务失败时不发布新会话，不残留部分歌单。未选择的会话不受影响。
新版继续导出同一结构，而不是导出原始 SQLite 文件。

新增可选的会话控制器与网络函数注入，供测试稳定模拟离线或同步失败；默认调用链
仍使用实际 Bilibili 服务。未引入新的用户配置项。
